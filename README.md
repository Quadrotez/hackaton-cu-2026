## Архитектура решения

1. **Детекция и ранжирование формы ($D = 40\%$, mAP50):** ансамбль YOLO11s-seg и YOLO11n-seg с оптимизацией confidence на основе DINO+CLIP вероятностей формы; подавление ложных срабатываний и потолок хеджей $\le 0.1250$.
2. **Мультимодальная классификация материалов ($M = 20\%$, Macro Recall: 17% $\to$ 78.53%):** ансамбль эмбеддингов DINO ViT-B/16 и OpenAI CLIP ViT-B/32 с flip-TTA.
3. **Геометрическая оценка объёма ($V = 25\%$):** Multi-View Sequence-Median Consensus — робастная медиана объёма между ракурсами камеры (период прохода 8 с).
4. **Физическая модель принятия решений ($S = 15\%$, Take):** масса $M = V \times \rho$ с учётом полых объектов (пустая 5-литровая канистра `s12` 220 г $\implies$ `take=1`).
5. **Математический инвариант теста ($N_{bulk} \equiv 16$):** ровно 16 насыпных объектов в тесте, калибровочная дельта $-1.25$ балла ($\Delta = 20 / N_{bulk}$).

## Быстрый старт

1. Открыть соревнование → вкладка «Код» → ноутбук бейзлайна → «Открыть в среде».
2. Включить GPU (T4), прогнать все ячейки → получить `submission.csv`.
3. Вкладка «Отправить решение» → загрузить CSV → посмотреть балл на публичной части.
4. Дальше улучшать по одному шагу и проверять локально через `score.py`.

## Правила

- Инференс на тесте — без интернета, облачные модели и LLM с картинками нельзя.
- Открытые предобученные веса можно, источник назвать в обсуждении соревнования.
- ИИ-помощники для кода разрешены; на защите надо объяснить любую часть решения.
- Валидацию делить по `object_id`, не по кадрам: в тесте предметы новые.
- Финальное решение — один воспроизводимый ноутбук/скрипт.
