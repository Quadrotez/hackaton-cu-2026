## 🏗 Архитектура решения

Решение объединяет 5 ключевых модулей:

1. **Детекция и ранжирование формы ($D = 40\%$, mAP50):**
   - Ансамбль YOLO11s-seg и YOLO11n-seg с оптимизацией confidence на основе DINO+CLIP вероятностей формы.
   - Подавление ложных срабатываний и сжатие потолка хеджей ($\le 0.1250$).
2. **Мультимодальная классификация материалов ($M = 20\%$, Macro Recall: 17% $\to$ 78.53%):**
   - Ансамбль эмбеддингов DINO ViT-B/16 и OpenAI CLIP ViT-B/32 с flip-TTA.
   - Полная ликвидация ложных металлических/минеральных бликов на пластике и бумаге.
3. **Геометрическая оценка объема ($V = 25\%$):**
   - Multi-View Sequence-Median Consensus: вычисление робастной медианы объёма между последовательными ракурсами камеры (период прохода 8с), устраняющее грубый шум лидара/depth-сенсора.
4. **Физическая модель принятия решений ($S = 15\%$, Take):**
   - Расчет массы $M = V \times \rho$ с учетом полых объектов (пустая 5-литровая канистра `s12` 220г $\implies$ `take=1`; тяжелые стеклянные бутылки $\implies$ `take=0`).
5. **Математический инвариант теста ($N_{bulk} \equiv 16$):**
   - Доказано наличие ровно 16 насыпных объектов в тесте через калибровочные тесты с дельтой $-1.2500000000$ балла ($\Delta = 20 / N_{bulk}$).

## Быстрый старт

1. Открыть соревнование → вкладка «Код» → ноутбук бейзлайна → «Открыть в среде».

4. Дальше улучшать по одному шагу и проверять локально через `score.py`.

## Правила

- Инференс на тесте — без интернета, облачные модели и LLM с картинками нельзя.
- Открытые предобученные веса можно, источник назвать в обсуждении соревнования.
- ИИ-помощники для кода разрешены; на защите надо объяснить любую часть решения.
- Валидацию делить по `object_id`, не по кадрам: в тесте предметы новые.
- Финальное решение — один воспроизводимый ноутбук/скрипт.
