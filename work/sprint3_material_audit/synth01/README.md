# synth01: остановлен на проверке происхождения

**Обновление:** после появления независимого background mapping выполнен A/B на поднаборе с подтверждённым foreground. См. [протокол и результаты запуска](README_run.md). Далее — исторический preflight, до появления mapping.

Выполнен только preflight. Сами 600 RGB-D кадров доступны. Но ни COCO, ни все 600 `meta.json`, ни локальная документация не предоставляют карту исходных foreground RGB/depth кадров, патчей и трансформаций. `attributes.object_id` и `instance` подтверждают лишь разметку видимой области, не происхождение пикселей. Проверка на точные дубликаты полных RGB кадров из detector handoff не распространяется на перенесённые, преобразованные или смешанные патчи.

| Фолд | Учебные реальные кадры/объекты пары | Synth после фильтра метаданных, metal/plastic | Synth с подтверждённым foreground |
|---|---:|---:|---:|
| 1 | 93 / 17 | 47 / 168 | 0 |
| 2 | 88 / 17 | 45 / 165 | 0 |
| 3 | 88 / 18 | 45 / 171 | 0 |
| 4 | 98 / 18 | 44 / 174 | 0 |
| 5 | 97 / 18 | 39 / 170 | 0 |

Preflight пересёк `train_image_ids`, потребовал ровно одну аннотацию (`instance==1`), наличие трёх файлов RGB-D/mask и совпадение пары `(material, object_id)` с разрешённым реальным train. Таблица не утверждает, что у прошедших фильтр кадров один донор пикселей. Эродированный interior-only ROI с полной поддержкой операторов внутри маски исключил бы чтение снаружи маски, но не решил бы отсутствие provenance RGB-D внутри неё. Для чистого A/B нужен манифест генерации, указывающий источники обоих каналов и преобразования, или воспроизводимая проверка эквивалентного уровня. Наличие RGB-D файлов и вычислительные ресурсы — не блокеры.

Из корня:

```sh
set -o pipefail
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  work/sprint3_material_audit/synth01/preflight.py \
  2>&1 | tee work/sprint3_material_audit/synth01/preflight.log
```

При повторе передать `--out work/sprint3_material_audit/synth01/preflight_replica.json`. Обучения, прогнозов, Δ, churn и сабмитов для `synth01` нет; `run01` не менялся.
